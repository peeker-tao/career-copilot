## 二、API 层封装（基础架构）

### 2.1 Axios 实例与拦截器 — `src/api/client.ts`

**职责：** 创建统一的 Axios 实例，配置请求/响应拦截器。

**实现要点（实际代码）：**

1. 创建 Axios 实例，`baseURL` 默认 `http://127.0.0.1:3002/api/v1`（通过 Vite 代理到后端）
2. **请求拦截器：** 从 localStorage 读取 accessToken，自动附加 `Authorization: Bearer <token>` 头
3. **响应拦截器 — 401 自动刷新队列：**
   - 使用 `isRefreshing` 标志 + `pendingQueue` 数组，避免并发刷新 Token
   - 首个 401 触发 refreshToken 请求，后续 401 排队等待刷新完成
   - 刷新成功后，遍历队列重放所有等待的请求
   - 刷新失败则清除 Token 并跳转登录页（通过 `window.location.href`）
4. **错误分级处理：**
   - `>= 500`：`message.error('服务器繁忙，请稍后重试')`
   - `403`：`message.warning('权限不足')`
   - `404`：`message.warning('请求的资源不存在')`
   - 请求取消（`axios.CanceledError`）静默处理
   - `__skipAuthRedirect` 配置项标记无需重定向的特殊请求
5. 超时时间 60 秒

```typescript
// 实际代码结构
const client = axios.create({
  baseURL: "/api/v1",
  timeout: 60000,
});

// 请求拦截器
client.interceptors.request.use((config) => {
  const token = localStorage.getItem("accessToken");
  if (token) config.headers.Authorization = `Bearer ${token}`;
  return config;
});

// 响应拦截器 — Token 刷新队列
let isRefreshing = false;
let pendingQueue: PendingTask[] = [];

client.interceptors.response.use(
  (response) => response.data,
  async (error) => {
    if (axios.isCancel(error)) return Promise.reject(error);
    if (!error.response) {
      message.error("网络错误，请检查连接");
      return Promise.reject(error);
    }
    const { status, config } = error.response;
    if (status === 401 && !config.__skipAuthRedirect) {
      if (!isRefreshing) {
        isRefreshing = true;
        try {
          const res = await axios.post("/api/v1/auth/refresh", {
            refreshToken: localStorage.getItem("refreshToken"),
          });
          localStorage.setItem("accessToken", res.data.accessToken);
          isRefreshing = false;
          pendingQueue.forEach(({ resolve }) => resolve(res.data.accessToken));
          pendingQueue = [];
          config.headers.Authorization = `Bearer ${res.data.accessToken}`;
          return client(config);
        } catch {
          localStorage.clear();
          window.location.href = "/login";
        }
      } else {
        return new Promise((resolve) => {
          pendingQueue.push({ config, resolve });
        }).then((token) => {
          config.headers.Authorization = `Bearer ${token}`;
          return client(config);
        });
      }
    }
    // 错误分级提示
    if (status >= 500) message.error("服务器繁忙，请稍后重试");
    else if (status === 403) message.warning("权限不足");
    else if (status === 404) message.warning("请求的资源不存在");
    return Promise.reject(error);
  },
);
```

**实现要点：**

- `logout()` 清除 localStorage 中的 Token，重置所有状态为初始值，跳转 `/login`
- `fetchProfile()` 在应用启动和页面加载时调用，填充 user 信息
- `fetchStats()` 获取用户统计数据（面试次数、平均分等）
- 不使用 `persist` 中间件，通过 localStorage 手动管理 token

## 十四、开发注意事项

### 14.1 样式约定

- 使用 Ant Design 组件自带样式，通过 `ConfigProvider` 设置主题色（`#1677ff` Ant Design 6 默认）
- 面试对话等复杂交互页面使用 CSS Modules 隔离样式
- **未使用** TailwindCSS / postcss / autoprefixer

### 14.2 状态管理原则

- **Zustand 5** 管理全局状态（认证信息、面试会话、简历状态等），共 6 个 Store
- 页面内临时状态使用 React 本地 `useState` / `useReducer`
- URL 参数使用 React Router 的 `useParams` / `useSearchParams`

### 14.3 错误处理原则

- 所有 API 调用使用 `try-catch` 包裹
- Axios 拦截器统一处理 401（Token 刷新队列）和网络错误
- 页面级错误使用 Ant Design `message.error()` / `notification.error()` 提示
- 不可恢复的错误显示 `ErrorBoundary` 降级 UI

### 14.4 性能注意事项

- 简历列表、面试历史列表数据量大时分页加载
- ECharts 图表组件使用 `React.lazy()` 加载
- Socket.IO 连接在页面卸载时及时关闭
- 面试消息列表渲染注意性能优化

### 14.5 环境变量

```env
# .env.development (项目根目录 frontend/)
VITE_BACKEND_API_BASE_URL=http://127.0.0.1:3002
VITE_USE_MOCK=true
VITE_BASE_URL_NAME=

# .env.production
VITE_BACKEND_API_BASE_URL=https://api.career-copilot.com
VITE_USE_MOCK=false
VITE_BASE_URL_NAME=
```

### 14.6 Mock 系统

- 通过 `VITE_USE_MOCK=true` 开启 Mock（开发环境默认开启）
- Mock 文件位于 `src/mock/` 目录，共 7 个模块文件
- 拦截 Axios 请求并返回模拟数据，无需后端即可开发

### 14.7 路由与导航

- 使用 `react-router-dom 7` 的路由懒加载（`lazy`）
- `AppNav` 导航组件包含 8 个导航项：Home、Resume、Interview、CareerPlan、JobMatching、Resources、QuestionBank、Profile
- 面试页面（`/interview/:id`）全屏模式，隐藏侧边栏
