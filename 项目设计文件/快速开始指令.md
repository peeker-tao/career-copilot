## 1. 环境要求

| 工具 | 版本要求 | 获取方式 |
|:----:|:--------:|----------|
| **Git** | 任意 | `winget install Git.Git` 或官网下载 |
| **Node.js** | ≥ 22 | `winget install OpenJS.NodeJS` 或官网下载 |
| **npm** | ≥ 10 | 安装 Node.js 后自带 |
| **Docker Desktop** | 任意 | `winget install Docker.DockerDesktop` 或官网下载 |
| **PostgreSQL 15+** | 15+ | 由 Docker 自动提供（见步骤 3） |
| **Redis 7+** | 7+ | 由 Docker 自动提供（见步骤 3） |
| **Python** | ≥ 3.9 | 可选（仅 Embedding 模型需要） |

### 快速安装命令（PowerShell）

```powershell
# 安装 Git
winget install Git.Git

# 安装 Node.js（会自动安装 npm）
winget install OpenJS.NodeJS

# 安装 Docker Desktop（安装后需手动启动）
winget install Docker.DockerDesktop
```

## 3. 启动数据库（Docker）

项目依赖 **PostgreSQL 15** 和 **Redis 7**，二者通过 Docker Compose 一键启动。

### 3.1 配置 Docker 国内镜像加速（首次使用）

Docker Hub 在国内访问不稳定。编辑 `C:\Users\你的用户名\.docker\daemon.json`：

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com",
    "https://docker.nju.edu.cn"
  ]
}
```

配置完后**重启 Docker Desktop**（系统托盘右键 → Restart）。

> **注意：** 关闭梯子再拉取镜像，否则可能冲突报错。

### 3.2 启动容器

```bash
cd backend

# 启动 PostgreSQL + Redis（后台运行）
docker compose up -d

# 确认两个容器都是 Up 状态
docker compose ps

# 验证数据库连接
docker compose exec postgres pg_isready -U app
# 应返回: /var/run/postgresql:5432 - accepting connections

# 验证 Redis 连接
docker compose exec redis redis-cli ping
# 应返回: PONG
```

### 3.3 停止数据库

```bash
cd backend
docker compose down         # 停止并删除容器
docker compose down -v      # 停止并删除容器 + 数据卷（会清空数据）
```

## 4. 配置后端环境变量

进入 `backend/` 目录，创建（或编辑）`.env` 文件：

```bash
cd backend
# .env 文件已存在则可直接编辑
```

最小配置（只填 API Key 即可使用）：

```env

# Redis
REDIS_URL="redis://localhost:6379/0"

# JWT — ⚠️ 生产环境必须修改为强密码
JWT_SECRET="your-jwt-secret-key-change-in-production"
JWT_ACCESS_EXPIRES="7d"
JWT_REFRESH_EXPIRES="30d"

# LLM 配置（根据使用的模型选择）
LLM_PROVIDER=                  # 可选，显式指定 openai / dashscope / deepseek，留空则自动检测
OPENAI_API_KEY="sk-xxx"
OPENAI_BASE_URL="https://api.openai.com/v1"
OPENAI_MODEL="gpt-4o-mini"     # 可选，默认 gpt-4o-mini
DASHSCOPE_API_KEY="sk-xxx"
DASHSCOPE_BASE_URL="https://dashscope.aliyuncs.com/compatible-mode/v1"
DASHSCOPE_MODEL="qwen-turbo"   # 可选，默认 qwen-turbo
# DASHSCOPE_WORKSPACE_ID="ws-xxx"  # 可选，DashScope 工作空间 ID（仅通义千问需要）
DEEPSEEK_API_KEY="sk-xxx"      # 推荐使用 DeepSeek（性价比高）
DEEPSEEK_BASE_URL="https://api.deepseek.com/v1"
DEEPSEEK_MODEL="deepseek-chat" # 可选，默认 deepseek-chat

# Embedding 配置（用于 RAG 知识库向量化）
# 默认使用本地模型（BAAI/bge-small-zh-v1.5），无需 API Key，离线运行

# 如果要用本地模型，EMBEDDING_PYTHON_PATH 可指定 Python 解释器路径
# EMBEDDING_PYTHON_PATH="./.venv/Scripts/python.exe"

# 文件上传

# SMTP 邮件配置（使用真实邮箱时填写）
SMTP_ENABLED=true
SMTP_HOST=smtp.qq.com          # QQ 邮箱
SMTP_PORT=587                  # 587(TLS) / 465(SSL)

SMTP_USER=your@qq.com

SMTP_FROM=Career Copilot <your@qq.com>

# 管理后台（admin-frontend Vite 开发服务器）
VITE_ADMIN_DEV_PORT=4177                          # 管理后台开发服务器端口
VITE_ADMIN_API_URL="http://localhost:3002"         # 管理后台 API 代理目标地址
```

## 10. 运行项目

需要同时启动 **3 个终端**，每个终端运行一个服务。

### 终端 1：后端（端口 3002）

```bash
cd backend
npm run start:dev
# 服务启动后: http://localhost:3002
# Swagger 文档: http://localhost:3002/api-docs
```

### 终端 2：用户前端（端口 5173）

```bash
cd frontend/frontend
yarn run dev
# 服务启动后: http://localhost:5173
```

### 终端 3：管理后台（端口 4177）

```bash
cd backend/admin-frontend
npm run dev
# 服务启动后: http://localhost:4177
```

## 11. Prisma Studio — 修改用户权限

Prisma Studio 是 Prisma 自带的数据库图形化管理界面，可以用来直接修改数据库中的数据。

### 11.1 启动 Prisma Studio

```bash
cd backend
npx prisma studio
# 浏览器会自动打开 http://localhost:5555
```

### 11.2 将普通用户提升为管理员

1. 在 Prisma Studio 界面中点击 **`User`** 模型
2. 找到你要修改的用户
3. 双击该用户的 **`role`** 字段
4. 将 `"user"` 改为 `"admin"`
5. 按 **回车 / Enter** 保存
6. 修改后该用户即可访问管理后台的 `/admin` 接口

### 11.3 其他常用操作

| 操作 | 方法 |
|:----:|------|
| 修改用户密码 | 在 User 表中编辑 `passwordHash` 字段（需先手动 bcrypt 加密） |
| 删除测试数据 | 选中记录 → 键盘按 **Delete** 键 |
| 添加新用户 | 点击 User 表顶部的 **Add Record** 按钮 |
| 查看简历数据 | 点击 **Resume** 模型 |
| 查看面试记录 | 点击 **Interview** 模型 |
| 执行自定义 SQL | 不适用（Prisma Studio 只支持可视化编辑，不支持 SQL 查询） |

## 12. 常见问题与解决方法

### 12.1 Docker 相关

#### Q: Docker 拉取镜像失败（超时 / EOF 错误）

**原因：** Docker Hub 被墙或梯子冲突。

**解决：**
```powershell
# 1. 关闭梯子（VPN/代理）
# 2. 重启 Docker Desktop（系统托盘右键 → Restart）
# 3. 确保 daemon.json 已配置国内镜像源
# 4. 重新拉取
docker compose up -d
```

#### Q: Docker Desktop 启动失败

**原因：** WSL 2 未安装或未启用虚拟化。

**解决：**
```powershell
# 以管理员身份运行 PowerShell
dism.exe /online /enable-feature /featurename:Microsoft-Windows-Subsystem-Linux /all /norestart
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
# 重启电脑后安装 WSL2 内核更新包
# https://learn.microsoft.com/zh-cn/windows/wsl/install
```

#### Q: 端口 5432 或 6379 已被占用

**原因：** 本地已安装 PostgreSQL 或 Redis 服务。

**解决：** 停止本地服务后再启动 Docker 容器。
```powershell
# 停止本地 PostgreSQL 服务
Stop-Service postgresql* -ErrorAction SilentlyContinue

# 停止本地 Redis 服务（如果有）
Stop-Service redis* -ErrorAction SilentlyContinue

# 或者修改 docker-compose.yml 中的端口映射
# 例如: "5433:5432" 将容器 5432 映射到主机 5433
```

### 12.2 后端相关

#### Q: `npx prisma migrate dev` 报错连接不上数据库

**原因：** Docker 容器未启动或 `.env` 中 `DATABASE_URL` 配置错误。

**检查：**
```bash
# 检查容器是否运行
docker compose ps

# 检查环境变量配置
type .env | findstr DATABASE_URL
# 应输出: DATABASE_URL="postgresql://app:app123456@localhost:5432/career_copilot"
```

#### Q: `npm run start:dev` 报端口 3002 被占用

**原因：** 上次运行的进程未关闭。

**解决（PowerShell）：**
```powershell
Get-NetTCPConnection -LocalPort 3002 -ErrorAction SilentlyContinue |
  ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
```

**解决（CMD）：**
```cmd
netstat -ano | findstr :3002 | findstr LISTENING && for /f "tokens=5" %a in ('netstat -ano ^| findstr :3002 ^| findstr LISTENING') do taskkill /f /pid %a
```

#### Q: `prisma generate` 报错 `Engine not found`

**原因：** Prisma 引擎下载失败（网络问题）。

**解决：**
```bash
# 设置国内镜像下载 Prisma 引擎
set PRISMA_ENGINES_MIRROR=https://registry.npmmirror.com/-/binary/prisma
npx prisma generate
```

#### Q: AI 功能返回 `401` 或 `403`

**原因：** API Key 未配置或配置错误。

**解决：**
1. 检查 `.env` 中 API Key 是否正确
2. 确认 API Key 余额充足
3. 如果使用 DeepSeek，确认 `DEEPSEEK_BASE_URL` 为 `https://api.deepseek.com/v1`

#### Q: 邮件发送失败（重置密码等）

**原因：** SMTP 配置错误或 QQ 邮箱授权码过期。

**解决：** 登录 QQ 邮箱 → 设置 → 账户 → 生成授权码，替换 `.env` 中的 `SMTP_PASS`。

#### Q: Token 过期

**原因：** JWT 默认 `access_token` 有效期 7 天，过期需重新登录或刷新。

**解决：** 调用 `/auth/refresh` 接口刷新 Token，或重新登录。

### 12.3 前端相关

#### Q: `yarn install` 报错

**原因：** Yarn 版本不兼容或网络问题。

**解决：**
```bash
# 使用 npm 代替 yarn
cd frontend/frontend
rm yarn.lock  # 删除 yarn.lock
npm install
npm run dev
```

#### Q: 前端页面白屏 / 请求 404

**原因：** Vite 代理配置不正确，或后端未启动。

**解决：**
1. 确认 `frontend/frontend/.env` 中 `VITE_BACKEND_API_BASE_URL=http://localhost:3002`
2. 确认后端已在终端 1 中成功启动
3. 检查浏览器控制台网络请求，查看具体报错

#### Q: 前端页面请求 CORS 报错

**原因：** 后端 CORS 配置未正确允许前端源。

**解决：** 正常情况下后端已配置 CORS，如果出现此问题，检查 `backend/src/main.ts` 中的 CORS 配置。

### 12.4 管理后台相关

#### Q: 管理后台访问 `/admin` 接口提示 403

**原因：** 当前用户不是管理员角色。

**解决：** 使用 Prisma Studio 将用户 `role` 改为 `admin`（见[步骤 11](#11-prisma-studio--修改用户权限)）。

#### Q: 管理后台页面打不开

**原因：** 管理后台开发服务器未启动或端口被占用。

**解决：**
```bash
cd backend/admin-frontend
npm run dev
# 默认端口 4177，可在 .env 中通过 VITE_ADMIN_DEV_PORT 修改
```

### 12.5 Embedding 模型相关

#### Q: Python 相关报错（Embedding Worker）

**原因：** 未安装 Python 或缺少 `fastembed` 包。

**解决：**
```bash
# 安装 Python 依赖
pip install fastembed

# 下载 Embedding 模型
python scripts/download_model.py

# 如果下载慢，使用国内 HuggingFace 镜像
$env:HF_ENDPOINT = "https://hf-mirror.com"
python scripts/download_model.py
```

## 附录：完整启动流程速查

以下是一个完整的**最小启动流程**（从 Clone 到运行）：

```powershell
# 1. Clone
git clone https://github.com/peeker-tao/career-copilot.git
cd career-copilot

# 2. 启动数据库
cd backend
docker compose up -d

# 3. 安装后端
npm install

npx prisma migrate dev

# 4. 安装前端
cd ../frontend/frontend
yarn install

# 5. 安装管理后台
cd ../../backend/admin-frontend
npm install

# 6. 启动三个服务（分别开三个终端）
# 终端 1: cd backend && npm run start:dev
# 终端 2: cd frontend/frontend && yarn run dev
# 终端 3: cd backend/admin-frontend && npm run dev
```

完成后访问：
- 用户前端：`http://localhost:5173`
- Swagger 文档：`http://localhost:3002/api-docs`
- 管理后台：`http://localhost:4177`
- 数据库管理：`http://localhost:5555`（需运行 `npx prisma studio`）
