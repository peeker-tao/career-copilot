## 一、后端项目初始化

### 1.1 环境要求

| 工具 | 版本 |
|:----:|:----:|
| Node.js | ≥ 22 |
| npm | ≥ 10 |
| PostgreSQL | 15+ |
| Redis | 7+ |
| Docker | 可选（用于启动数据库） |

### 1.2 初始化步骤

#### ① 安装 NestJS CLI（如未安装）

```bash
npm install -g @nestjs/cli
```

#### ② 创建 NestJS 项目

```bash
cd D:\gitclone\软件工程实训（二）\career-copilot
nest new backend --skip-git --package-manager npm --strict --language TypeScript
```

#### ③ 安装核心依赖

```bash
cd backend

# 生产依赖
npm install @nestjs/config @nestjs/jwt @nestjs/passport @nestjs/platform-socket.io @nestjs/websockets @nestjs/bullmq @prisma/client prisma passport passport-jwt bcrypt bullmq ioredis socket.io class-validator class-transformer pdf-parse mammoth multer openai rxjs

# 开发依赖
npm install -D @types/bcrypt @types/multer @types/passport-jwt @types/pdf-parse ts-node nodemon
```

> **注意：** 如果安装的 Prisma 版本为 7.x，需要降级到 5.x 以获得传统模式支持：
>
> ```bash
> npm install prisma@5 @prisma/client@5
> ```

#### ④ 初始化 Prisma

```bash
npx prisma init
```

#### ⑤ 配置环境变量

编辑 `.env` 文件，配置数据库连接等信息：

```env
# Database
DATABASE_URL="postgresql://app:app123456@localhost:5432/career_copilot"

# Redis
REDIS_URL="redis://localhost:6379/0"

# JWT
JWT_SECRET="your-jwt-secret-key-change-in-production"
JWT_ACCESS_EXPIRES="15m"
JWT_REFRESH_EXPIRES="7d"

# LLM 配置
LLM_PROVIDER=                  # 可选，显式指定 openai / dashscope / deepseek，留空则自动检测
OPENAI_API_KEY="sk-xxx"
OPENAI_BASE_URL="https://api.openai.com/v1"
OPENAI_MODEL="gpt-4o-mini"     # 可选，默认 gpt-4o-mini
DASHSCOPE_API_KEY="sk-xxx"
DASHSCOPE_BASE_URL="https://dashscope.aliyuncs.com/compatible-mode/v1"
DASHSCOPE_MODEL="qwen-turbo"   # 可选，默认 qwen-turbo
DEEPSEEK_API_KEY="sk-xxx"
DEEPSEEK_BASE_URL="https://api.deepseek.com/v1"
DEEPSEEK_MODEL="deepseek-chat" # 可选，默认 deepseek-chat

# 文件上传
UPLOAD_DIR="./uploads"
MAX_FILE_SIZE=10485760

# 服务器
PORT=3002
```

#### ⑥ 配置 Prisma Schema

`prisma/schema.prisma` — 定义数据模型（User、Resume、Interview、InterviewMessage、CareerPlan），详见 `项目设计文件/database_design.md`。

#### ⑦ 生成 Prisma Client

```bash
npx prisma generate
```

#### ⑧ 验证编译

```bash
npx nest build
```

编译成功应无任何错误输出。

#### ⑨ 启动数据库（Docker）

> ⚠️ **国内网络说明：** Docker Hub 在国内访问不稳定。推荐**关闭梯子**，使用国内镜像加速。

**首次使用需先配置 Docker 国内镜像加速（只需配一次）：**

在 `C:\Users\你的用户名\.docker\daemon.json` 中写入以下内容：

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com",
    "https://docker.nju.edu.cn"
  ]
}
```

配置完后**重启 Docker Desktop**（系统托盘右键 → Restart），然后启动容器：

```bash
# 启动 PostgreSQL + Redis（后台运行）
docker compose up -d

# 查看容器是否正常运行
docker compose ps

# 查看启动日志
docker compose logs

# 停止并删除容器
docker compose down

# 彻底清理（删除容器 + 数据卷）
docker compose down -v
```

> 📌 **镜像说明：** `docker-compose.yml` 中已配置国内镜像地址 `docker.m.daocloud.io/library/...`，如有梯子想用官方源，把 `docker.m.daocloud.io/library/` 前缀去掉即可。

#### ⑩ 验证数据库连接

确认 PostgreSQL 和 Redis 已就绪：

```bash
# 检查 PostgreSQL 是否可连接
docker compose exec postgres pg_isready -U app

# 检查 Redis 是否可连接
docker compose exec redis redis-cli ping
# 应返回 PONG

# 或使用 npx 验证 Prisma 连接
npx prisma db push --accept-data-loss
```

#### ⑩ 运行数据库迁移

```bash
npx prisma migrate dev --name init
```

#### ⑪ 启动开发服务器

若报错端口占用，可使用下面表格中的指令释放端口

```bash
npm run start:dev
```

服务运行在 <http://localhost:3002>

### 1.4 Docker 国内镜像加速配置

Docker Hub 在国内访问不稳定，推荐配置国内镜像加速（替代开梯子）：

**配置步骤：**

| 步骤 | 操作 | 说明 |
|:----:|------|------|
| 1 | **关闭梯子（VPN/代理）** | 梯子和国内镜像源会有冲突 |
| 2 | 编辑 `C:\Users\你的用户名\.docker\daemon.json` | 写入镜像加速源地址 |
| 3 | **重启 Docker Desktop** | 系统托盘右键 → Restart |
| 4 | `docker compose up -d` | 从国内镜像拉取并启动 |
| 5 | `docker compose ps` | 确认两个容器都是 `Up` 状态 |

**daemon.json 完整配置参考：**

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://dockerproxy.com",
    "https://docker.nju.edu.cn",
    "https://mirror.ccs.tencentyun.com"
  ]
}
```

> **如果拉取镜像时卡住或报 `EOF` 错误：** 一般是梯子没关干净或者 Docker Desktop 没重启。先关梯子，重启 Docker Desktop，再试一次。

**Provider 自动检测逻辑（工厂模式）：**

| 优先级 | Provider | 激活条件 | 默认模型 |
|:------:|----------|:---------:|:--------:|
| ⭐ | 显式指定 | `.env` 中 `LLM_PROVIDER=openai/dashscope/deepseek` | 按指定 |
| 1 | OpenAI | `OPENAI_API_KEY` 有值且非占位符 | gpt-4o-mini |
| 2 | 通义千问 | `DASHSCOPE_API_KEY` 有值且非占位符 | qwen-turbo |
| 3 | DeepSeek | `DEEPSEEK_API_KEY` 有值且非占位符 | deepseek-chat |

**环境变量说明：**

```env

**System Prompt 构建器 (`interview.system.ts`)：**

根据职位、难度、简历上下文动态生成面试官提示词，定义三种输出格式：

| 类型 | 触发场景 | 说明 |
|:----:|----------|------|

|:----:|------|----------|
| `followUp` | 继续追问 | 保存追问内容，不增加 questionCount |
| `nextQuestion` | 进入下一题 | 保存新题，questionCount++ |
| `complete` | 结束面试 | 更新 status=completed，记录分数 |

**AI 面试引擎 (`ai-interview.service.ts`)：**

```typescript

  generateFirstQuestion(context: InterviewContext): Promise<FirstQuestionResult>

  // 评估回答 + 决定后续动作
  evaluateAndContinue(context, userAnswer, history): Promise<EvaluationResult>
}
```

**面试对话流程：**

```

  │

  ├─ 读取简历上下文（如有 resumeId）
  ├─ 调用 AiInterviewService.generateFirstQuestion()
  └─ 保存首题 → 返回 { interview, firstQuestion }
       │
       ▼ 用户答题

  └─ 发送 ai_message_done（含评分 + 下一动作）

### [x] T-025 — AI 缓存服务（AiCacheService）✅

| 字段 | 内容 |
|:----:|------|
| **负责人** | 陶宏阳 |
| **文件** | `src/ai/ai-cache.service.ts` |

> **实现要点：**
>
> - **缓存键：** `SHA256(systemPrompt + userMessage)` — 内容寻址，相同请求命中相同缓存
> - **存储后端：** Redis，通过 `RedisService` 统一存取（`cacheGet` / `cacheSet`）
> - **注入方式：** `@Optional()` — 无 Redis 可用时跳过缓存，零侵入降级
> - **TTL 策略：** 按场景前缀分类（详见下方 TTL 表）
>
> **场景 TTL 配置：**
>
> | 缓存前缀 | TTL | 说明 |
> |:--------:|:---:|------|
> | `resume:parse` | 7 天 | 简历解析结果长期稳定 |
> | `resume:rewrite` | 7 天 | 简历润色/分析结果 |
> | `resume:screening` | 1 小时 | 简历筛选需实时 |
> | `interview:question` | 24 小时 | 同岗位题目可复用 |
> | `interview:evaluate` | 1 小时 | 评估需最新判断 |
> | `interview:report` | 1 小时 | 报告需最新评分 |
> | `interview:voice` | 24 小时 | 语音分析结果 |
> | `career:plan` | 24 小时 | 职业规划可复用 |
> | `career:insight` | 24 小时 | 市场洞察数据 |
> | `learning:recommend` | 24 小时 | 学习资源推荐 |
> | `job:matching` | 1 小时 | 匹配度需实时准确 |
> | `job:recommend` | 24 小时 | 岗位推荐 |
> | `question:generate` | 24 小时 | 题库生成 |
> | `general` | 1 小时 | 默认 TTL（兜底） |
>
> **调用流程：**
>
> ```
> callLLM(systemPrompt, userMessage, temperature, 'interview:question')
>   → 计算 SHA256 缓存键
>   → Redis.cacheGet(key) → 命中 → 直接返回
>   → 未命中 → 调用 LLM
>   → Redis.cacheSet(key, result, 86400) → 返回
> ```

### [x] T-026 — 简单 RAG 服务（SimpleRagService）✅

| 字段 | 内容 |
|:----:|------|
| **负责人** | 陶宏阳 |
| **文件** | `src/ai/rag/simple-rag.service.ts` |

> **实现要点：**
>
> - **嵌入模型：** `BAAI/bge-small-zh-v1.5`（本地 ONNX Runtime，通过 Python Worker 进程加载）
> - **向量维度：** 512 维（ONNX 版本输出）
> - **向量存储：** Redis Hash（每份文档存两条：`rag:{ns}:{key}` 存全文 + 向量 + 元数据，`rag:{ns}:vec:{key}` 存向量 + 内容 + 元数据）
> - **相似度算法：** Cosine Similarity（JS 端计算，扫描全部向量后取 Top-K）
> - **Top-K：** 默认 K=3
> - **增强方式：** 检索到的知识片段格式化为 `[参考 N]\n（相似度: X%）\n{content}` 后追加到 System Prompt 末尾
> - **命名空间：** 按场景隔离（如 `interview` 面试问答知识库）
> - **已填充数据：** 29 条面试题（Java / Python / 前端 / 系统设计 / 行为 / 数据库 / 网络 七类）
> - **Windows 兼容：** Python 子进程 stdin/stdout 强制 UTF-8 编码，解决 CP936/GBK 中文乱码
>
> **接口定义：**
>
> ```typescript
> @Injectable()
> export class SimpleRagService {
>   // 检索最相似的知识
>   async retrieve(namespace: string, query: string, topK?: number): Promise<RagResult[]>
>
>   // 增强调用：嵌入 → 检索 → 格式化 → 追加到 systemPrompt
>   async augmentCall(
>     systemPrompt: string,
>     userMessage: string,
>     namespace: string,
>   ): Promise<{ augmentedPrompt: string; contexts: string[] }>
> }
>
> interface RagResult {
>   text: string;
>   score: number;
>   metadata?: Record<string, unknown>;
> }
> ```
>
> **工作流程：**
>
> ```
> 1. SimpleRagService.augmentCall(systemPrompt, userMessage, 'interview')
> 2. LocalEmbedderService 将 userMessage 通过 stdin 发送至 Python Worker
> 3. Python Worker (embed_worker.py) 加载 BGE 模型计算 512 维向量，通过 stdout 返回
> 4. 扫描 Redis 中全部 rag:interview:vec:* 键，加载已有向量
> 5. JS 端逐条计算 Cosine Similarity，取 Top-3
> 6. 格式化检索到的知识为 [参考 N]（相似度: X%）→ 追加到 systemPrompt
> 7. 返回增强后的 systemPrompt 和检索到的上下文
> ```
>
> **依赖组件：**
>
> ```
> ┌────────────────┐     stdin/stdout JSON      ┌──────────────────┐
> │ LocalEmbedder  │◄──── (UTF-8 编码) ────────►│  Python Worker   │
> │  (NestJS)      │                             │  embed_worker.py │
> │                │◄──── {ok,embedding,id} ────►│  BGE-small-zh    │
> └────────────────┘                             └──────────────────┘
> ```

### 7.5 开发注意事项

- **样式方案：** Ant Design 组件 + CSS 变量（`index.css` 全局定义）+ 独立 CSS 模块（按页面/组件拆分），不使用 TailwindCSS
- **Mock 数据：** 纯 TypeScript 对象模拟（`src/mock/`），通过环境变量 `VITE_USE_MOCK=false` 控制开关，非 MSW
- **状态管理：** Zustand 管理全局状态，共 6 个 Store（`useAuthStore` 用户/Token、`useResumeStore` 简历、`useInterviewStore` 面试、`useCareerStore` 职业规划、`useVoiceStore` 语音、`useToastStore` 通知）
- **API 请求：** `src/api/client.ts` 中 Axios 实例已配置请求/响应拦截器（自动附加 JWT、Token 自动刷新、请求队列防重复）
- **页面加载：** 所有受保护页面均使用 `React.lazy()` 懒加载，减少首屏包体积
