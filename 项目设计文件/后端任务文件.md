## 三、公共基础架构

### T-002 统一响应格式与异常处理

| 字段 | 内容 |
|------|------|
| **负责人** | 赵原一 |
| **工时** | 0.5天 |

**实现文件：**

#### `src/common/interceptors/response.interceptor.ts` — 统一响应拦截器

将所有 Controller 返回的数据包装为统一格式：

```typescript
// 输出格式
{
  code: 200,
  message: "success",
  data: { ... }   // 业务数据
}
```

**实现要点：**

- 使用 NestJS `@Injectable()` + `implements NestInterceptor`
- 成功响应自动设置 `code` 为状态码、`message` 为对应消息
- `data` 字段包裹业务返回数据
- 排除文件流等特殊响应

#### `src/common/filters/http-exception.filter.ts` — 全局异常过滤器

```typescript
// 错误输出格式
{
  code: 400,          // HTTP 状态码
  message: "参数错误",
  error: "具体错误信息" // 开发环境可包含详细堆栈
}
```

**实现要点：**

- 捕获 `HttpException` 及其子类
- 对 `class-validator` 校验失败返回 422 + 字段级错误详情
- 区分开发/生产环境（生产不暴露堆栈）

#### `src/common/pipes/validation.pipe.ts` — 参数校验管道

- 全局注册 `ValidationPipe`
- 配置 `transform: true` 自动类型转换
- 配置 `whitelist: true` 剔除未装饰的属性
- 自定义错误消息格式

创建 `src/common/prisma.service.ts`（或使用 NestJS Prisma Module）：

2. 已注册抛 409 Conflict 异常
3. bcrypt.hash(password, 10) 加密密码

5. 生成 Access Token（15min）和 Refresh Token（7d）
6. 返回用户信息 + Token 对

**登录逻辑：**

1. 根据 email 查找用户
2. 不存在抛 401 Unauthorized
3. bcrypt.compare() 校验密码
4. 校验失败抛 401
5. 生成 Token 对并返回

**Token 刷新逻辑：**

1. 校验 refreshToken 是否有效（JWT verify）
2. 从 payload 中提取 userId
3. 生成新的 Access Token 和 Refresh Token
4. 可选：旧 Refresh Token 加入黑名单（Redis）

```typescript
export class ResumeParser {
  async extractText(filePath: string): Promise<string> {
    const ext = path.extname(filePath).toLowerCase();
    if (ext === '.pdf') {
      // 使用 pdf-parse 提取 PDF 文本
      const dataBuffer = fs.readFileSync(filePath);
      const pdfData = await pdfParse(dataBuffer);
      return pdfData.text;
    } else if (ext === '.docx') {
      // 使用 mammoth 提取 Word 文本
      const result = await mammoth.extractRawText({ path: filePath });
      return result.value;
    }
    throw new BadRequestException('不支持的文件格式');
  }

    // 调用 AI 服务，传入 System Prompt + 简历文本
    // 返回结构化 JSON
    return this.aiService.parseResume(text);
  }
}
```

#### `resume.processor.ts` — Bull 队列消费者

```typescript
@Processor('resume-parser')
export class ResumeProcessor {
  @Process()
  async handleParsing(job: Job<{ resumeId: string }>) {
    const { resumeId } = job.data;
    try {
      // 1. 从 DB 获取简历记录
      const resume = await this.prisma.resume.findUnique({ where: { id: resumeId } });
      // 2. 提取文本
      const text = await this.resumeParser.extractText(resume.fileUrl);
      // 3. LLM 结构化提取
      const parsedData = await this.resumeParser.parseWithLLM(text);
      // 4. 更新数据库
      await this.prisma.resume.update({
        where: { id: resumeId },
        data: {
          parsedData: parsedData as any,
          skills: parsedData.skills || [],
          status: 'completed',
        },
      });
    } catch (error) {
      // 解析失败更新状态
      await this.prisma.resume.update({
        where: { id: resumeId },
        data: { status: 'failed' },
      });
    }
  }
}
```

```typescript
@Injectable()
export class AiCacheService {
  async getOrSet(
    systemPrompt: string,
    userMessage: string,
    prefix: string,
    fetcher: () => Promise<Record<string, unknown>>,
  ): Promise<Record<string, unknown>> {
    const key = this.buildKey(systemPrompt, userMessage);
    const cached = await this.redisService.cacheGet(key);
    if (cached) return cached;
    const result = await fetcher();
    await this.redisService.cacheSet(key, result, this.getTTL(prefix));
    return result;
  }
}
```

## 二十、开发注意事项

### 20.1 错误处理

- 所有 Service 层抛出自定义 HttpException（含状态码和中文错误消息）
- 全局异常过滤器捕获并统一格式返回
- WebSocket 异常通过 `ws-exception.filter.ts` 处理

### 20.2 数据校验

- 所有 DTO 使用 `class-validator` 装饰器（如 `@IsEmail`, `@MinLength`, `@IsOptional`）
- 全局 `ValidationPipe` 注册在 `main.ts` 中
- 敏感信息（密码哈希）永远不在日志中输出

### 20.3 安全

- 密码 bcrypt 加密（saltRounds = 10）
- JWT Token 过期时间：Access 15 分钟，Refresh 7 天
- 所有需要认证的接口使用 `@UseGuards(JwtAuthGuard)` 保护
- Refresh Token 使用后可轮换（旧 token 加入 Redis 黑名单）
- 文件上传做类型校验（防止恶意文件)

### 20.4 性能

- 列表接口强制分页（最大 pageSize 50）
- JSONB 查询使用 `@>` 操作符走 GIN 索引
- LLM 调用设置超时（默认 30s，流式模式 60s）
- 简历解析使用异步队列处理，不阻塞 HTTP 响应
- WebSocket 连接做好心跳检测和断线重连

### 20.5 AI 服务配置

```typescript
// AI Provider 选择逻辑
const provider = process.env.OPENAI_API_KEY
  ? new OpenAIProvider()
  : process.env.DASHSCOPE_API_KEY
    ? new DashScopeProvider()
    : new DeepSeekProvider();
```

**推荐开发配置：** 使用 DeepSeek（性价比高，兼容 OpenAI SDK）
**推荐生产配置：** 使用通义千问（国内访问稳定）或 OpenAI（效果最好）
